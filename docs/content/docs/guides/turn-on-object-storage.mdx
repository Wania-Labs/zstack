---
title: Turn on object storage
description: Bind R2 for ObjectStore. Keys are tenant-scoped. Sign through the Worker until S3 API tokens are set.
---

Object storage is `configured` in `product.config.ts`. `ObjectStore` always exists. Keys are opaque strings, not filenames. Feature code calls the port. It does not import the R2 SDK.

## Defaults

| Binding / env                                                                                 | Missing                                         | Present                      |
| --------------------------------------------------------------------------------------------- | ----------------------------------------------- | ---------------------------- |
| Worker `OBJECTS`                                                                              | In-memory fake                                  | R2 bucket bytes              |
| `R2_ACCESS_KEY_ID` + `R2_SECRET_ACCESS_KEY` + `CLOUDFLARE_ACCOUNT_ID` + `OBJECTS_BUCKET_NAME` | Sign intents return Worker `/api/objects/<key>` | aws4fetch presigns an S3 URL |

`alchemy:dev` binds Alchemy local R2. That is not a cloud bucket on the author's account. `alchemy:deploy` provisions a real bucket named from the stack. The Worker binding cannot presign. Tokens are required for that.

Presign is effectively Alchemy-only. Plain wrangler declares no R2 binding, so it stays on the in-memory fake and the tokens do nothing. Alchemy binds `CLOUDFLARE_ACCOUNT_ID` and `OBJECTS_BUCKET_NAME` from the bucket. You supply the two tokens.

## Key scopes

The Worker scopes every key to the caller:

| Prefix                | Who                                             |
| --------------------- | ----------------------------------------------- |
| `user/<userId>/…`     | The signed-in user                              |
| `org/<activeOrgId>/…` | Members of the active Team (membership checked) |

Any other prefix returns `403`. Malformed keys return `400`: empty segments, `.` or `..` segments, control characters, backslashes, more than 1024 characters, or bad percent-encoding. The rules live in `apps/api/src/modules/objects/access.ts`.

## Steps

1. Prefer `pnpm alchemy:dev` so `OBJECTS` is bound. The wrangler escape hatch stays on the in-memory fake.
2. Build keys under `user/<userId>/` or `org/<activeOrgId>/`.
3. Call `signUpload` / `signDownload` from product code. Use the returned intent:

   - `{ kind: "worker", path, method }` → `PUT` / `GET` `/api/objects/<key>` on this Worker. Sign-in required. The Worker enforces key scopes.
   - `{ kind: "presigned", url, method }` → the client talks to R2 directly.

   `ObjectStore` does not authorize keys. No route exposes `signUpload` / `signDownload` today. If you add one, check the key with `authorizeObjectKey` first. A presigned URL bypasses the Worker and its scope check.

4. Optional. Create R2 S3 API tokens and set them where Alchemy reads env (root `.env` or shell locally, a stage file on deploy):

```bash
R2_ACCESS_KEY_ID=…
R2_SECRET_ACCESS_KEY=…
```

5. Restart `alchemy:dev` or redeploy so the Worker sees the env.

## What you should see

- Anonymous `PUT` / `GET` / `DELETE` `/api/objects/*` → `401`
- Key outside your scopes → `403`
- Malformed key → `400`
- Upload over 25 MB → `413` (early on a large `content-length`, otherwise mid-stream)
- Missing object → `404`
- Successful Worker upload or delete → `204`
- Empty key passed to the port → `ObjectStoreError` ("object key must be a non-empty opaque string")
- Default sign TTL is 3600 seconds

Every Worker `GET` sends `X-Content-Type-Options: nosniff`, `Content-Security-Policy: sandbox`, and `Cache-Control: private, no-store`. PNG, JPEG, GIF, and WebP are served `inline`. Everything else, SVG included, is `Content-Disposition: attachment`. Stored content types are reduced to a validated `type/subtype`.

The 25 MB cap applies to Worker-mediated uploads. Use presigned URLs for larger files.

The staff console origin does not forward `/api/objects/*`. Object routes are reachable from the customer app only.

Do not inherit an author-account bucket in a clone. Physical names come from the personalized Alchemy stack.
