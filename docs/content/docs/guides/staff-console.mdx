`apps/admin` is the staff TanStack Start shell. It uses the same Hono API as the customer app. Access is gated by product staff capabilities exposed on `staff.me`.

## Promote a user

### Bootstrap the first admin

1. Sign up on http://localhost:3000.
2. Run:

```bash
STAFF_EMAIL=you@example.com pnpm db:seed
```

3. Open http://localhost:3001/login and sign in as that user.

### Promote more users in the console

After one staff account exists, open **Users** in the admin app. Search by email and set role to `admin`, `support`, `operations`, or `owner`. Set role to `user` to clear staff access. Only `admin` and `owner` can change roles. `support` and `operations` can list users.

## How the gate works

Better Auth's Admin plugin supplies `user.role`. Product code maps roles (`admin`, `support`, `operations`, `owner`) to `staffCapabilities` on the request context. oRPC `staff.me` rejects non-staff callers.

The admin app keeps private console content behind a `/_console` layout. That layout redirects anonymous visitors to `/login`, then waits for `staff.me` before rendering the sidebar shell. Signed-in non-staff users see a reject screen with sign-out.

User list and role changes call Better Auth `admin.listUsers` / `admin.setRole` (not new oRPC staff routes).

## Origin and API routing

The staff console is its own origin. Better Auth trusts it through `ADMIN_URL`:

| Context       | `ADMIN_URL`                                               |
| ------------- | --------------------------------------------------------- |
| `alchemy:dev` | Defaults to `http://localhost:3001`                       |
| Wrangler      | `apps/api/.dev.vars` (`http://localhost:3001` in example) |
| Deploy        | Required, `https://` (custom domain or workers.dev URL)   |

Sign-in from an origin that is not `BETTER_AUTH_URL` or `ADMIN_URL` fails with `403` `INVALID_ORIGIN`.

Deployed, `apps/admin/src/routes/api/$.ts` forwards only `/api/auth/*` and `/api/rpc/*` to the API service binding. Object routes and the Polar webhook are not reachable from the admin origin (`404`). SSR guards forward the browser cookie, so a hard refresh inside `/_console` keeps the session. See [Deploy](/docs/guides/deploy).

## UI stack

Admin uses the same shadcn base-nova setup as web. Add components with:

```bash
pnpm --filter @zstack/admin exec shadcn add button
```
