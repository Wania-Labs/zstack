title: Capabilities

`product.config.ts` records structural capability intent for the clone. It never holds secrets. Nothing reads it today: not the API runtime, not `alchemy.run.ts`, not CI. Actual on/off comes from Alchemy resources in `infra/*` plus empty vs set env. Keep the file in sync so humans and agents share one table.

## States

| State        | Meaning                                                                                   |
| ------------ | ----------------------------------------------------------------------------------------- |
| `core`       | Always on with a free/local default (Compose, Better Auth, Paraglide)                     |
| `absent`     | No Effect Layer, no Alchemy resource, no fake production fallback                         |
| `configured` | Code and bindings exist; behavior stays off, console, or fake until secrets or flags flip |
| `enabled`    | Reserved for live-by-default once a clone commits to a vendor; not used today             |

Values are typed as `CapabilityState`. A typo fails `pnpm typecheck`.

Empty credentials are the day-one default. Prefer console, Compose, and fake models over the author's SaaS accounts.

## What ships today

| Capability          | State in config                           | Live default                                                                                                                   |
| ------------------- | ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| Postgres            | `core` (`deploy.database: "planetscale"`) | Compose locally; PlanetScale on `alchemy:deploy`                                                                               |
| Auth / orgs / staff | `core` (`auth`)                           | Better Auth against Compose                                                                                                    |
| i18n                | `core` (`i18n`)                           | Paraglide in `packages/i18n`. No vendor secret                                                                                 |
| Email               | `configured`                              | Console until `EMAIL_FROM` + `BENTO_*`                                                                                         |
| Observability       | `configured`                              | Off until `SENTRY_DSN` / `VITE_SENTRY_DSN*`                                                                                    |
| AI                  | `configured`                              | Fake models until `AI_GATEWAY_API_KEY`                                                                                         |
| Object storage      | `configured` (`objectStorage`)            | In-memory fake until `OBJECTS` is bound. Sign intents are Worker paths until R2 S3 API tokens are set, then aws4fetch presigns |
| Feature flags       | `configured` (`flags`)                    | In-memory map. `FEATURE_FLAG_*` env overlays. Missing keys return the call-site default                                        |
| Billing             | `configured` (`billing`)                  | Fake until `POLAR_ACCESS_TOKEN`. With a token: Polar checkout/portal, webhooks, ledger, entitlements, usage                    |
| Analytics           | `configured` (`analytics`)                | No-op until `POSTHOG_API_KEY` / `VITE_PUBLIC_POSTHOG_KEY`. Capture API only. No flags, no replay                               |
| Workflows / queues  | `configured`                              | In-memory fakes until `JOBS` / `EXAMPLE_WORKFLOW`. Alchemy binds both on the API Worker                                        |

Feature-flag SaaS, KV snapshots, and admin flag authoring are not shipped. Product flags stay on the in-memory map.

## How to turn one on

1. Confirm the capability is `configured` (or `core`) in `product.config.ts`.
2. Bind the secrets for that vendor. Under Alchemy, each key must be listed in `infra/api.ts` `env`.
3. Restart `alchemy:dev` or the Worker so env reloads.
