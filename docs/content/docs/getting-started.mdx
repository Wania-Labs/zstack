You will scaffold a consumer product, start Compose Postgres, migrate, and open the customer app.

## Fastest path: hand it to your agent

Name the product, pick your coding agent, and copy the prompt. Paste it into the agent from an empty folder. It scaffolds with the right `--agent-tools`, sets local secrets, starts Postgres, runs the stack, and reports which optional vendors are still off. The **Terminal** tab shows the same steps as commands.

## Scaffold

```bash
npm create @wanialabs/zstack@latest my-product
pnpm create @wanialabs/zstack@latest my-product
yarn create @wanialabs/zstack@latest my-product
bunx @wanialabs/create-zstack@latest my-product

# non-interactive + coding-agent packs (symlink skills into Cursor/Claude dirs):
pnpm create @wanialabs/zstack@latest my-product --yes --agent-tools=cursor,claude --skills=symlink

# name the product (default: title-cased directory + @<slug> packages):
pnpm create @wanialabs/zstack@latest acme --name Acme --scope acme --yes
```

Any launcher works; the clone is a pnpm workspace and always installs with pnpm. Names use letters, digits, spaces, and `. ' & -`, up to 32 characters.

Pin `@latest` on first scaffold. Bare `pnpm create @wanialabs/zstack` can reuse a cached CLI.

`pnpm-workspace.yaml` sets `allowBuilds.sharp: false` so a system libvips (Arch, Homebrew) does not force sharp to compile. create-zstack also sets `SHARP_IGNORE_GLOBAL_LIBVIPS=1` for the install it runs. If an older clone already compiled and failed, run `SHARP_IGNORE_GLOBAL_LIBVIPS=1 pnpm install` in that clone.

From a clone of this authoring repo you can point at the local tree (giget uses `git:`, not `file:`):

```bash
pnpm create-zstack my-product --template git:./ --yes
# or:
ZSTACK_TEMPLATE=git:$(pwd) pnpm create-zstack /tmp/zstack-smoke --force --yes
```

`@wanialabs/create-zstack` downloads the template with giget, strips authoring-only paths, personalizes identity from the target directory (or `--name` / `--scope`; `--keep-identity` keeps `zstack` / `@zstack`), optionally writes coding-agent packs (`--agent-tools` / `--mcp` / `--skills`), and installs with nypm. Default remote: `gh:Wania-Labs/zstack`. Requires Node.js `>=22.5`. The clone always includes `AGENTS.md`, `.agent/playbooks/`, and `.agent/skills/`. See [create-zstack](/docs/reference/create-zstack) and [Coding agents](/docs/guides/coding-agents) (includes a paste-ready agent setup prompt).

## First run in the clone

```bash
cd my-product
cp apps/api/.dev.vars.example apps/api/.dev.vars
printf 'BETTER_AUTH_SECRET=%s\n' "$(openssl rand -base64 32)" | tee -a .env >> apps/api/.dev.vars
pnpm dev:services
pnpm db:migrate && pnpm db:seed
pnpm alchemy:dev
```

| Surface       | URL                   |
| ------------- | --------------------- |
| Customer app  | http://localhost:3000 |
| Staff console | http://localhost:3001 |
| API Worker    | http://localhost:8787 |

Sign up on the customer app (`/sign-up`), name a Team when prompted, then open the appshell under `/t/<slug>`. Members (`/t/<slug>/members`) is the example team feature to copy. Auth screens read copy from `@zstack/i18n` (Paraglide, `en` only).

Promote yourself to staff with:

```bash
STAFF_EMAIL=you@example.com pnpm db:seed
```

Then open the staff console at http://localhost:3001/login. Use **Users** to promote more people after the first seed.

## Secrets for local smoke

Generate one `BETTER_AUTH_SECRET` with `openssl rand -base64 32` and write it to two gitignored files:

| File                 | Read by                                 |
| -------------------- | --------------------------------------- |
| root `.env`          | `pnpm alchemy:dev` (Alchemy CLI)        |
| `apps/api/.dev.vars` | Plain `wrangler dev` (copy the example) |

Alchemy never reads `.dev.vars`, `.env.local`, or `.env.development`. The `printf … | tee` line above appends the same value to both. dotenv keeps the last duplicate key, so it overrides the example placeholder.

Local origins need no setup. `BETTER_AUTH_URL=http://localhost:3000` and `ADMIN_URL=http://localhost:3001` are the defaults under `alchemy:dev` and in `.dev.vars.example`. Deploy requires https values. See [Deploy](/docs/guides/deploy).

Optional vendors (Bento, Sentry, AI Gateway, Polar, PostHog) stay off until you set their env vars. See [Capabilities](/docs/concepts/capabilities).

## Prefer Alchemy for full stack

`pnpm alchemy:dev` starts api, web, and admin together and points Hyperdrive at Compose. The wrangler + Vite dual-process path is an escape hatch. Details live in [Local development](/docs/local-development).

## Work on zstack itself

```bash
git clone git@github.com:Wania-Labs/zstack.git
cd zstack
pnpm install               # also compiles Paraglide via @zstack/i18n prepare
pnpm dev:services
pnpm db:migrate && pnpm db:seed
cp apps/api/.dev.vars.example apps/api/.dev.vars
printf 'BETTER_AUTH_SECRET=%s\n' "$(openssl rand -base64 32)" | tee -a .env >> apps/api/.dev.vars
pnpm alchemy:dev
```

Docs for the authoring site:

```bash
cd docs
pnpm install
pnpm dev
```

Docs run on http://localhost:4000 with a separate lockfile.
